# INC-2288: Sustained CPU from an OS denial-analysis daemon

## Summary

A denial-analysis daemon held roughly 20% CPU sustained on mid-prod-f3 for six days, spiking to full utilisation during filesystem scans.

## Signature

Detected under the stable signature `host.cpu.saturation:mid-prod-f3`.

## Timeline

- **D0, 03:00** Denial volume rises sharply. The audit dispatcher starts the analysis daemon, which stays resident. Source: audit log.
- **D+6, 14:20** Daemon identified in a process snapshot as the top CPU consumer. Source: bridge.
- **D+6, 15:05** Audit event dispatcher deactivated. Daemon exits and CPU recovers. Source: host.

## Resolution

Deactivated the audit event dispatcher so the denial stream no longer reached the analysis daemon.

## Superseded

Platform security standard SEC-STD-14 (2026-01-30) requires the audit event dispatcher to remain active on production hosts. Deactivating it is no longer an available resolution, and doing it here destroyed the evidence that would have identified the source domain.

## Gaps

- The source domain of the denials was never identified, because the denial log stopped being collectable once the dispatcher was deactivated.
