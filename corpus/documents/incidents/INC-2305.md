# INC-2305: Container memory limit reached in an orchestrated service

## Summary

A service container was restarted repeatedly on reaching its memory limit. The limit was the container's, not the host's: the host it ran on held ample free memory throughout and never entered exhaustion.

## Signature

Detected under the stable signature `container.memory.limit:svc-prod-k2`.

## Timeline

- **D0, 04:12** Container reaches its memory limit and is restarted by the orchestrator. Source: orchestrator.
- **D0 to D+1** Restart repeats eleven times. Host memory and swap stay flat throughout. Source: OS metrics.
- **D+1, 13:40** Cache bounded and the limit raised to match the working set. Source: change registry.

## Resolution

Bounded the cache and raised the container's memory limit. No host-level change was made or needed.

## Gaps

- No host-level resource attribution was captured, because the container limit bounded the consumer before the host could feel it. A host under genuine pressure would need that attribution.
